# H5 版（网页版）

iOS 上架审核期间，让 iPhone 用户先在浏览器或微信里用上。H5 版和 App 是同一份代码（`apps/mobile`），用 Expo 的 Web 导出生成静态网页，部署在 `https://training.dreamerlab.cn/h5/`，与接口同域名（不需要跨域配置）。

## 不影响 App 的依据

- 浏览器专用的实现都放在 `*.web.ts` 文件里（`src/lib/fs.web.ts`、`src/lib/mediaLibrary.web.ts`），安卓和 iOS 打包不会包含它们
- 页面里的 H5 分支都用 `Platform.OS === 'web'`（`src/lib/platform.ts` 的 `isWeb`）判断，App 上不会执行
- `app.config.ts` 只在设置了环境变量 `WEB_BASE_PATH` 时才多一项网页部署路径；`public/` 目录只有网页导出会读
- H5 是单独的构建命令、单独的容器、单独的流水线；不改后端、不改数据库、不动 App 的打包和热更新

## 和 App 的差别

| 功能 | H5 版 |
| --- | --- |
| 登录、引导、导入（文件、相册、拍照、粘贴）、题库、训练、批改、整卷、背诵、作文、看板、兑换码 | 与 App 相同 |
| 拍手写稿 | 调用系统相机或相册选图 |
| 每日训练提醒、解析完成的系统通知 | 没有（浏览器排不了本地通知），设置页不显示「通知」分组；结果在消息中心看 |
| 口述背诵、语音作答、在线支付、邀请海报 | 不显示入口（`src/lib/flags.ts` 的 `WEB_UNSUPPORTED`），不管服务端开关 |
| 版本更新提示 | 没有，网页打开就是最新版 |
| 客服二维码 | 不能存相册，改为长按识别或保存 |
| 导出题库 | 生成后由浏览器下载 |
| 从微信「用其他应用打开」直接导入 | 没有，引导用户先存到手机再选文件 |
| 购买入口开关（后台 7.8） | 接口只认 ios / android，H5 跟随 **安卓** 的开关 |
| 登录设备（6.11） | 显示「网页版」 |
| 作答草稿、登录态 | 存在浏览器本地存储；清除浏览器数据或换浏览器后要重新登录，草稿不跨设备 |
| 没传完的照片、文件 | 刷新页面后要重新选（浏览器里的临时文件地址刷新即失效） |

## 构建

```bash
cd peetraining-web
pnpm install --frozen-lockfile
pnpm --filter mobile build:h5        # 产物在 apps/mobile/dist-h5，部署路径 /h5
```

可用环境变量：`WEB_BASE_PATH`（默认 `/h5`）、`API_BASE_URL`（默认生产接口）、`H5_OUT_DIR`。
构建后 `dist-h5/version.json` 记录版本号、构建时间和提交，部署后访问 `/h5/version.json` 可确认线上是哪一次构建。

## 部署结构

```
用户 ──HTTPS──▶ 阿里云 dreamer-nginx ──/h5/──▶ 容器 training-h5（Nginx，只放静态文件）
                         └──/api/v1/──▶ 京东云 training-api（原样，不变）
```

- `apps/mobile/deploy/h5/nginx.conf`：容器内的 Nginx 配置（入口页不缓存、带哈希的文件长期缓存、找不到的路径回入口页）
- `apps/mobile/deploy/h5/deploy.sh`：在阿里云入口机上发布或回退。只动 `/opt/training-h5` 和容器 `training-h5`，镜像复用机器上 `dreamer-nginx` 的镜像，不用拉镜像、不用镜像仓库密码

### 第一次上线要做的事（只做一次）

1. 入口 Nginx（`dreamer-nginx`）在 `training.dreamerlab.cn` 的 `server` 块里加（写法参照现有的 `/admin/`）：

   ```nginx
   location = /h5 { return 301 /h5/; }
   location /h5/ {
       set $training_h5 training-h5:80;
       proxy_pass http://$training_h5;      # 带变量：容器重建后会重新解析地址；原路径原样转发
       proxy_set_header Host $host;
       proxy_set_header X-Real-IP $remote_addr;
   }
   ```

   然后 `docker exec dreamer-nginx nginx -t && docker exec dreamer-nginx nginx -s reload`。只加这一段，不改已有的 `location`。
2. OSS 存储桶的跨域规则要允许来源 `https://training.dreamerlab.cn` 用 `PUT`、`GET`，允许全部请求头（H5 和管理后台一样是浏览器直传）。管理后台已经在用浏览器直传，这条规则多半已经有；上线后传一个文件确认。
3. 发布一次（见下），打开 `https://training.dreamerlab.cn/h5/`。

### 发布

云效流水线「peetraining-h5上线」（代码源：云效 `peetraining-web` 的 `h5` 分支）：

1. Node 22 构建：`npm i -g pnpm@10.28.0 && pnpm install --frozen-lockfile && pnpm --filter mobile build:h5`
2. 打包：`tar -czf h5.tgz -C apps/mobile dist-h5 -C deploy/h5 nginx.conf deploy.sh`
3. 主机部署到阿里云入口机（与 peetraining-admin 同一个主机组）：解压出 `deploy.sh` 后执行 `bash deploy.sh <包路径>`

手工发布：把 `h5.tgz` 传到阿里云入口机，`tar -xzf h5.tgz deploy.sh && bash deploy.sh h5.tgz`。

回退：在入口机执行 `bash /opt/training-h5/current/deploy.sh rollback`。
下线：`docker rm -f training-h5`，并去掉入口 Nginx 的 `/h5/` 段。
