# T07 备考档案、规则参数与功能开关

- 仓库：后端 + 前端（先后端，后前端）
- 依赖：T03
- 计划完成：10/7
- 状态：审查中

## 目标

新用户能设置专业课、目标分、阶段和时长；所有可调参数和开关都在服务端。

## 范围 · 后端部分（在 peetraining-server 里做，先合并并打契约标签）

- 专业课：名称、代码（选填）、满分、目标分，最多 4 门，免费版最多 3 门（PRD v3 13.1）；考试年份；目标院校专业（选填）
- 备考档案：阶段（含是否手动）、每日时长、提醒时间；初试日期按年份从配置读取
- rule_params 表与读取缓存，初始值按 PRD v3 第 11、13 节写入
- feature_flags：全部 / 指定用户；App 启动拉取；关闭时相关接口返回 404；写 ADR 0009

## 范围 · 前端部分（在 peetraining-web 里做，先执行 pnpm gen:api）

- 1.1 你考哪门专业课、1.2 设定目标分、1.3 备考安排（引导进度条 1–3 / 5）
- 6.9 备考设置（删除专业课时的二次确认文案按设计稿）
- 引导中途退出后再次启动回到中断步骤

## 参考

- docs/prd.md 第 6 节模块 1（1.1–1.3）、第 9 节 6.9、第 11.4 节
- docs/design/pages/m1_subject、m1_target、m1_setup、m6_prep

## 验收

- 新用户能完成 1.1–1.3，数据正确保存；可跳过目标分
- 改阶段或时长从次日生效，改目标分立即生效
- 对指定账号打开一个开关后，只有该账号能看到对应入口

## 不做

- 卡片范围以外的页面、接口和重构；发现需要的，记到 docs/open-questions.md

## 记录（开发中填写）

- 实现要点：
  - 后端 internal/profile：考试年份（附距考试天数与系统建议阶段，前端不算规则）；备考档案首次创建立即生效，之后改阶段或每日时长写入待生效字段、北京时间次日起生效（读取时到期落地），与系统建议不同记为手动选择；目标院校、提醒、作文周目标、通知开关立即生效
  - 专业课：建课同时建自建题库（一门一个）；免费版最多 3 门、会员 4 门（D12，额度取自 rule_params.quota），第 4 门返回 QUOTA_EXCEEDED；目标分不超过满分，可清除；用户改作文课判断记为 user；删除专业课先删 OSS 题库前缀再删数据（题库、资料、整卷与练习记录）
  - rule_params 读取缓存（internal/params，30 秒）；功能开关：全部 / 指定用户、App 随 /bootstrap 拉取、受控接口关闭时 404（FeatureGate + flagGuards，ADR 0009）
  - 契约 api-v0.1.1：ExamYear 增加 days_to_exam、suggested_stage；nullable 字段生成 nullable.Nullable 以区分「没传」与「null」
  - App：1.1（考试年份、添加 / 删除专业课、免费版第 4 门弹出开会员、目标院校）、1.2（满分 100 / 150 / 300、目标分默认 70%、先不设这门、先跳过）、1.3（倒计时、系统推荐阶段、每日时长）、5 步进度条；引导中途退出按 onboarding_step 回到中断的步骤；1.4 先放「先跳过，进入 App」（导入流程 T12）；6.9 备考设置（专业课与目标、增删、目标院校、初试日期、时长、阶段与建议理由、作文周目标、生效说明）
- 偏离计划的地方与原因：
  - 修了 rules.Day 读写 DATE 列差一天的问题（北京时间 0 点换成 UTC 会落到前一天），新增 Day.Date / DayFromDateColumn
  - 6.5 会员中心还没做（T25），额度不足弹层先跳到占位页
- 需要手动验证的步骤：
  - 真机走一遍 1.1 → 1.3：添加 1–3 门课、第 4 门弹会员提示；中途杀掉 App 重进回到中断的步骤
  - 6.9 改阶段后当天首页不变、次日生效（T16 首页接上后验证）
  - 在生产对自己账号打开一个开关（feature_flag_users），确认只有自己能看到入口（对应入口在后续卡出现）
