# T21 模拟考试切题后继续识别手写稿

- 状态：开发完成（自动化通过，真机待复验）
- 范围：模拟考试/整卷作答的拍照工具栏、按题后台识别、识别确认与交卷衔接。
- 用户要求：字数与拍照按钮对齐；拍完可以切题，照片不丢失；返回原题可核对，交卷采用未核对的结果。

## 实现计划

1. 工具栏垂直居中，字数靠右，允许长文案折行。
2. 照片与题号绑定，本地立即保存，上传后登记服务端任务，复用已有视觉大模型识别与原有 UI。
3. 页面切题不取消上传/识别；题内和答题卡显示上传、识别、待核对与失败状态。失败保留照片，可重试或明确弃用。
4. 手动交卷等待本机上传任务登记完成；已登记的识别任务可随卷提交，后台识别后默认确认再批改；截止时间仍以服务端为准，已登记的照片不会被当成空白答案。
5. 返回原题可编辑并确认识别结果；确认接口幂等，防止重试重复追加；验证切题、跨题异步完成、交卷、失败、恢复与截止时间边界。

## 发布约束

- 新增迁移 `00027_paper_handwriting.sql`，服务端迁移并发布后再分发新版 App。
- 未上传/未在截止时间前登记的本地照片不能在锁卷后新增；会保留在本机并明确提示，不伪称已提交。
- 系统挂起 App 后网络任务可能暂停；重新进入时恢复本地上传，已登记任务由服务端 Worker 继续。

## 行为说明

- 上传中可以直接切到下一题；本机照片保存到 App 文档目录，草稿和识别核对编辑分别按考试、题号持久化。
- 上传完成后向服务端登记任务，Worker 在后台识别。返回原题可核对并确认填入原答案；未核对直接交卷时由服务端默认采用。
- 手动交卷先等本机照片上传并登记；登记完成后可以交卷，服务端继续识别，全部处理完成再批改。已明确失败的照片需要先重试或弃用。
- 时间到仍按 deadline 锁卷；已登记照片保留并继续识别，未登记照片留在本机并显示未包含在答卷中的提示。
- 两张照片上传完成的先后不会改变答案顺序。前一张未处理时不能先确认后一张；核对过但没点确认的编辑在手动交卷时保存，再由 Worker 按拍照顺序追加。
- 确认响应丢失时本地保留待确认文字，暂时锁住该题输入，其他题仍可作答。恢复网络后先找回确认结果，再同步草稿，避免旧草稿覆盖已识别文字。

## 真机复验步骤

1. 在 390×844 和 1.3 倍字号下检查拍照按钮与右侧字数对齐、长字数提示折行。
2. 第一题拍照后立即切第二题继续打字，随后从答题卡回第一题，确认照片和识别结果仍在。
3. 同一题连拍两页，人工让第二张先上传完成，核对拼接顺序；修改第二页后直接交卷。
4. 分别在上传、识别、确认响应阶段断网，再恢复网络；确认原答案不丢、不重复追加。
5. 在手写稿识别中交卷、让考试倒计时归零、将 App 切到后台后重新进入，核对原题文字与最终批改。
