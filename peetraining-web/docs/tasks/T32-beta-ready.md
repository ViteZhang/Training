## 记录（开发中填写）

- 实现要点：
  - 埋点：POST /events 批量上报（契约 api-v0.19），服务端只收 PRD 15 节列出的事件、短的标量属性，键名像正文的（text、answer、content、stem、note、phone…）丢掉，写 log_type=event 的 JSON 日志由 SLS 采集；App 端 src/lib/analytics.ts 本地队列攒 20 条 / 30 秒 / 切后台时上报，接入登录、加专业课、导入、确认入库、开始与结束练习、作答、批改异议、整卷开始与交卷、作文提交、导出、兑换、回访、会员页、提分看板、添加官方题库、打开 App
  - 监控告警：API 按分钟在 Redis 计请求数与 5xx；Worker 每 5 分钟查接口错误率、队列积压、AI 失败率、AI 成本超预算，写 log_type=alert 的 ERROR 日志并推送钉钉 / 企业微信群机器人（ALERT_WEBHOOK_URL），30 分钟内不重复
  - 内容安全：之前只审上传的资料；补上 AI 输出的审核（dev-spec 九「AI 输出过审后才入库展示」）：生成新文字的能力（参考答案、讲解、变式题、命题、批改评语、考情分析）输出过内容安全，没过按不合格重试一次，再不过生成失败、不扣次数；审核服务不可用时不放行
  - 越权访问：TestIntegrationIDOR 按契约遍历全部带路径参数的 App 接口（87 个），用户 B 拿用户 A 的 ID 一律 404；请求体按 Schema 生成以通过校验，新接口自动纳入
  - 协议：docs/legal 写了用户协议、隐私政策、会员服务协议草稿（含上传声明、AI 内容仅供参考、预估分不代表实际成绩、侵权投诉渠道、四项隐私承诺、授权查看 72 小时、注销冷静期），须法务审核后在 7.8 发布
  - 契约 YAML 里重复定义的锚点（&id001 等，之前的生成脚本留下的）改成唯一名字，含义不变，严格的 YAML 解析器也能读
  - runbook 加「监控告警与埋点」「内测准备」；web 加 docs/qa-checklist.md（94 个 App 页面 + 15 个后台页面 × 五种状态 × 三台机器，问题清单，打包与分发清单）
