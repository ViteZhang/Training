# T28 管理后台：运营与质量

- 仓库：后端 + 前端（先后端，后前端）
- 依赖：T06、T25
- 计划完成：10/11
- 状态：审查中（生产待验证）

## 目标

能看内测数据、处理用户问题和质量问题，且看不到用户内容。

## 范围 · 后端部分（在 peetraining-server 里做，先合并并打契约标签）

- 后台账号：账号密码 + 短信两步验证（强制）；会话 8 小时；五种角色与权限声明
- 统计聚合表由 Worker 每小时汇总
- 7.1–7.7 所需接口；授权查看接口与日志；所有写操作审计

## 范围 · 前端部分（在 peetraining-web 里做，先执行 pnpm gen:api）

- 7.1 概览、7.2 用户、7.3 会员与订单、7.4 兑换码、7.5 资料解析监控、7.6 批改异议、7.7 用户反馈；水印；手机号脱敏

## 验收

- 客服账号在没有授权时调用任何接口都拿不到用户资料、题目或作答原文（集成测试）
- 授权后 72 小时内可查看，每次查看用户都收到消息，日志可查
- 能生成一批兑换码并导出

## 不做

- 卡片范围以外的页面、接口和重构；发现需要的，记到 docs/open-questions.md

## 记录（开发中填写）

- 实现要点：
  - 后台账号（internal/admin）：账号密码（bcrypt）+ 短信两步验证，所有账号强制；会话令牌 8 小时，库里只存哈希；15 分钟内错 5 次暂停；首次登录必须改初始密码；第一个管理员用 `api create-admin` 建（初始密码读 ADMIN_INITIAL_PASSWORD）
  - 权限：后台接口用独立的 adminAuth，App 的用户令牌拿不到后台接口、后台令牌也不能调 App 接口；每个后台接口在契约里声明 x-roles，AdminGate 从契约读取，没声明的一律拒绝（有单测保证每个后台接口都声明了角色）
  - 审计：所有写操作与敏感读（完整手机号、授权内容）由中间件写 admin_audit_logs，不提供删除接口
  - 用户内容不可见：db/queries/admin.sql 只有计数、状态与元数据；原文只在 admincontent.sql，经 notify.RecordAccess 校验授权（72 小时、范围内）、记 content_access_logs 并通知用户后读取
  - 统计：Worker 每小时把日指标、本周活跃、漏斗、热门专业课写进 stats_hourly，7.1 只读它
  - 7.2 加解析额度记为本周期赠送额度（quota_counters.bonus，迁移 00016），幂等；赠送会员、重新解析失败文件、发站内消息、封禁（同时作废刷新令牌）
  - 7.3 订单与退款（调 payment.Service.Refund）；7.4 批次生成、停用、明细（末 3 位）、单码查询、作废并收回会员
  - 7.5 解析成功率、平均与 P95 耗时、按格式统计、失败任务的识别日志（不含文件名与内容）、重跑、拍照建议、补偿额度；7.6 异议率、原因分布、抽检归因、授权查看题目与作答；7.7 反馈统计、回复到消息中心、授权查看资料、重新识别
  - 契约 api-v0.15：/admin/** 共 42 个接口
  - 前端（apps/admin）：两步登录、首次改密码、按角色菜单、水印、退出；7.1–7.7 页面；兑换码生成后当场导出 CSV
  - 修复：T27 消息中心的服务没有注入到 App 的路由依赖里（经完整路由调用会出错），本卡的集成测试经完整路由覆盖了 /messages
  - 新增依赖：golang.org/x/crypto（bcrypt，原为间接依赖）
- 偏离计划的地方与原因：
  - 兑换码只存哈希（D28），完整码只在生成时返回一次，所以「导出」分两种：生成时导出完整码；之后的批次导出只有末 3 位、状态与使用人（D37）
  - 「换高精度 OCR 重跑」先按原识别引擎重跑，高精度 OCR 接入后切换（D38）；「成本超预算」提醒放到 T29（AI 成本统计）
- 需要手动验证的步骤：
  - 生产：执行 `ADMIN_INITIAL_PASSWORD=… api create-admin <账号> <显示名> <手机号> admin` 建第一个管理员，用真实短信完成两步登录并改密码
  - 后台生成一批兑换码并导出，用 App 兑换一个，再在后台单码查询、作废，确认会员被收回
  - 用户在 App 意见反馈里勾选授权，客服在 7.7 查看资料，用户在消息中心收到通知；7.2 用户详情的操作记录里能看到
