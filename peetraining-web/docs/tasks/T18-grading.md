# T18 主观题批改、失分诊断与异议

- 仓库：后端 + 前端（先后端，后前端）
- 依赖：T17
- 计划完成：10/10
- 状态：审查中（真实模型待测）

## 目标

按用户资料里的采分点批改，这是产品的核心。

## 范围 · 后端部分（在 peetraining-server 里做，先合并并打契约标签）

- 主观题批改：逐采分点判定命中 / 部分 / 遗漏，引用考生原话，给建议；校验分值上限、总分、引用存在；≤ 8 秒
- 额度：每天免费 3 次，扣额度与写结果同一事务；失败不扣；待批改队列（额度用尽时存）
- 失分诊断按 11.7；更新掌握分与错题本
- 异议：改采分点后重批、提交复核重批，都不扣次数；授权勾选写 content_access_grants
- cmd/eval grading：读人工评分样本，输出偏差 ≤ 1 分比例与重批一致性

## 范围 · 前端部分（在 peetraining-web 里做，先执行 pnpm gen:api）

- 4.4 主观题（打字、语音入口（受「语音作答」开关控制，默认关闭）、拍照入口、草稿、剩余次数、限时作答）、4.6 AI 批改中、4.7 批改结果、4.8 批改异议、4.9 批改次数用完

## 记录（开发中填写）

- 实现要点：
  - 契约 v0.5.0（只加不改）：submitSubjective、getGrading、regradeAfterRubricChange、createDispute、listPendingGradings、submitPendingGradings
  - 新 AI 能力 grade_subjective（强模型、温度 0）：逐采分点判定命中 / 部分 / 遗漏、引用考生原话、原因、结构是否完整、1–3 条建议；服务端兜底校验：每个采分点都要判、命中给满分、遗漏 0 分、部分命中不超过分值、引用必须在考生答案里（忽略空白），不合格重试一次，再失败返回「批改失败，未扣次数」
  - 批改依据快照（PRD 11.14）：采分点版本、来源（用户确认 / AI 提取 / AI 生成 / 官方 / 没有采分点时按参考答案整体批改）、出处页；采分点缺分值或合计与满分不符时按满分平均分配；改采分点只影响之后的批改
  - 扣批改次数与写作答、批改、学习状态在同一事务；模型调用在事务外；并发把次数用完时改存待批改
  - 次数用完：答案存为待批改（queued_quota，不调模型），次日一键提交，按存入顺序批改到次数用完为止
  - 失分诊断（PRD 11.7）：每个采分点的失分按规则归入知识没掌握 / 答题不规范 / 时间不够（只在限时作答时判定），主失分类型写进错题本
  - 异议：复核重批一次（每次批改只能复核一次，复核出来的批改不能再复核）；改采分点后按新采分点重批；都不扣次数，新批改指向原批改，历史批改不变；以重批结果为准回算掌握分（25 ×（新得分率 − 旧得分率），非主知识点减半）和错题（满分时撤回这次收录的「没拿满分」错题）；勾选授权时写 content_access_grants，72 小时
  - make eval cap=grading：读 evals/private/grading.jsonl（没有时用公开示例），输出与人工偏差 ≤ 1 分的比例（门槛 80%）和三次重批一致性
  - App：4.4 主观题（打字作答、字数与建议字数、草稿每 5 秒存本地、今日剩余批改次数、限时作答开关、语音入口受开关控制、拍手写稿入口）、4.6 批改中（三步进度、采分点出处、15 秒后安抚文案）、4.7 批改结果（得分、命中计数、逐采分点判定与原话、批改依据与出处、失分归因与下一步、建议、掌握分变化、错题本、参考答案、「仅供参考」）、4.8 异议（四选一、采分点不对引导去改、改完一键按新采分点重批、授权勾选）、4.9 次数用完（会员对比、先对照参考答案、明天再批改）、训练页待批改一键提交、独立的批改结果页
- 偏离计划的地方与原因：
  - 批改同步返回（目标 8 秒内），没有走队列；失败直接告诉用户未扣次数、草稿保留可重试，比轮询简单可靠
  - 4.7 的「预估分变化」在 T22 接通；「看规范写法」在 T19 接通；「开通会员」在 T25 接通；语音作答与拍手写稿入口先提示（T19、语音开关默认关闭）
  - 限时作答先在客户端计时并上报 timed，建议用时倒计时在整卷（T21）里统一做
- 需要手动验证的步骤：
  - 用真实模型抽查 5 题，同一答案连续批改 3 次分差 ≤ 1 分（验收第 3 条；需要百炼域名放行与环境变量）
