# 0012 AI 主用与对照模型、提示词版本的选定方法

- 日期：2026-10-03
- 状态：提议（真实样本评测后补「结果」并改为已采纳）

## 背景

G3 关口（dev-spec 第十二节）要求各项 AI 能力在真实样本上达到 PRD 12.3 的门槛才能内测：题目导入识别正确率 ≥ 95%；
知识点原文一致率 ≥ 90%、采分点召回率 ≥ 85%；主观题批改与人工偏差 ≤ 1 分的比例 ≥ 80%；作文偏差 ≤ 10 分的比例 ≥ 75%；
手写识别字准确率 ≥ 95%。上线时调用的模型必须是已备案的国内模型（百炼为主，另一家国内平台对照）；
开发期用过的中转接口（AI_PROVIDER=relay）不是备案模型，只能用虚构数据做开发与对照，不能用于真实用户数据，也不能作为上线选型的依据（D20）。

## 决定

- 评测工具：`make eval cap=… args="…"`（cmd/eval）。每项输出门槛指标、每千次调用成本（AI_PRICES 配了价格才有）与时延 P50 / P95；
  `-model` 指定模型、`-prompt` 指定提示词版本（internal/ai/prompts/<能力>@<版本>.tmpl），`-record` 把结果追加到 evals/README.md
- 样本：真实样本与人工标注只放 evals/private/（已在 .gitignore 排除），不进仓库、不进日志；规模按 evals/README.md
- 选定顺序：
  1. 对每项能力，用百炼的候选模型（高阶、便宜各一）跑当前提示词版本，记录
  2. 不达标的先改提示词（新文件 @v2，不改旧版本，便于对比与回滚），再考虑换模型或调切题规则；每次改动重跑并记录
  3. 达标的候选里，按「达标 → 重批一致性 → 每千次成本 → 时延」排序选主用；另一家国内平台跑同一组样本，作为对照与故障时的备用
  4. 主用便宜档能否用便宜模型：便宜模型在该能力上达标就用（AI_PREFER_STRONG=false），否则所有能力都用高阶模型
- 写回：选定的模型名写进生产环境变量（AI_MODEL_STRONG、AI_MODEL_CHEAP、AI_ALT_*），选定的提示词版本改成能力定义里的默认版本（Def.Version）；
  上线后换模型或提示词走后台 7.8 灰度（候选版按比例放量 → 全量 / 回滚），每次放量前重跑对应评测
- 每次改 internal/ai 或提示词，提交前必须跑对应评测，低于门槛不合并（CLAUDE.md 必须遵守第 8 条）

## 放弃的方案与原因

- 只看公开评测榜单选模型：考研文科专业课的题型、采分点批改与榜单任务差别很大，必须用自己的样本
- 用中转接口的模型作为主用：不是备案模型，不能处理真实用户数据（D20）
