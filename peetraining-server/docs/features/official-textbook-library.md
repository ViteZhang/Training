## 1. 文档目的与确认范围

建立由运营维护的官方教材库，存放教材、讲义及可追溯原文。APP 用户只填写参考教材书名，生成缺失的参考答案前，系统先匹配指定教材并检索相关原文，再由大模型组织答案；原文不能覆盖的部分，按规则使用个人相关资料和模型已有知识补充。

本文件为现有 PRD v3 的增量需求。本模块发生冲突时，以本次用户确认的方案、三项修订和已确认设计稿为依据；未调整的题目来源、学习计划、评分、预估分与会员规则继续沿用原 PRD。开发前须将相关增量同步至研发仓库的 PRD、技术决策和任务卡，不能仅依赖聊天记录施工。

### 1.1 已确认决定

| 编号 | 已确认要求 |
| --- | --- |
| D-01 | 后台新增独立“官方教材库”，与“官方题库”区分，教材、讲义原文不作为题目管理 |
| D-02 | 教材库独立于题库项目，一本教材可跨专业课、跨官方题库项目复用 |
| D-03 | APP 仍只填书名，不要求上传教材、选择目录或增加教材阅读入口 |
| D-04 | 缺答案时，优先检索指定教材原文；个人相关资料补充；仍不足时使用模型已有知识 |
| D-05 | 教材库中的 PDF 全部页面统一走大模型识别，包含文字 PDF、扫描 PDF；不走传统 OCR |
| D-06 | APP 对未匹配、匹配歧义、未收录与检索无相关内容静默处理，不提示、不警告、不阻塞保存 |
| D-07 | 引入向量化索引，与中文全文检索结合；向量化模型调用由用户提供，凭证由服务端配置 |
| D-08 | 展示本次生成实际采用的教材依据，允许查看本题相关摘录，保留“AI 参考答案 · 待确认” |
| D-09 | 教材新增、修订、默认版本变化均不自动覆盖已有答案；主动更新须比较、采用后才生效 |
| D-10 | APP 严格沿用现有 UI tokens、页面布局、字体和组件规范 |
| D-12 | 主动更新成功生成候选扣一次，采用不再扣，失败不扣，放弃不退次 |
| D-11 | 设计稿已确认。用户已授权开始开发；生产发布仍按现有发布流程执行 |

### 1.2 设计稿的解释边界

设计稿中的教材、摘录、页码、统计数、进度、模型状态及检索结果均为演示数据，不得导入生产作为真实内容。画板的“模拟完成”“演示场景”等为评审控件，正式产品不提供这些按钮。

画板点击后立即完成校对、向量化或发布，是交互简化。实际产品必须完成真实任务和服务端检查后才转移状态。未覆盖的个人资料来源、权限拒绝和加载状态等，按本文补全，复用已有组件。

## 2. 背景与现状

2026-10-30 检查本地代码确认：

1. 每门专业课已保存参考教材书名列表，APP 有首次设置与备考设置入口。
2. `AnswerInput` 目前将书名和个人题库中相关知识点原文传给模型，没有按用户书名查询官方教材原文的链路。
3. 官方题库项目内已有简版“官方参考素材”，支持教材、讲义原文录入、切分，供后台编辑生成官方题目答案。
4. 现有素材通过 `project_id` 归属一个官方题库项目，缺少独立教材身份、出版版本、内容修订、发布与索引生命周期。
5. 现有官方素材相关段落主要按字面重合选择，没有本需求所需的完整混合检索能力。
6. 缺答案生成结果会保存在题目上；已有答案直接返回。既有资料、答案确认和历史批改规则必须兼容。

以上为本地代码事实，不代表线上部署状态或教材实际收录情况。不得把已有素材自动视作满足发布条件。

## 3. 目标、范围与术语

### 3.1 目标

- 运营能独立录入、识别、校对、发布和维护教材、讲义。
- 用户仅填书名，即可在需要生成答案时使用指定教材的相关原文。
- 系统准确区分“书名匹配”“找到相关段落”“答案实际采用依据”。
- 答案来源、教材版本和原文位置可核对、可追溯。
- 未匹配、无相关原文或检索故障时保留正常学习流程，APP 静默降级。

### 3.2 首版范围

独立后台入口、教材身份与版本、别名与学科范围、PDF / DOCX / Markdown / TXT / 粘贴文字导入、PDF 大模型识别、原文校对、异步任务与恢复、全文与向量索引、检索试用、发布下架、项目关联、APP 书名匹配、全部缺答案生成入口接入、引用摘录、答案更新比较、旧数据迁移、模型配置状态与后台聚合缺口统计。

### 3.3 范围外

整本阅读或下载、教材商城、外部教材自动抓取、公共教材搜索引擎、用户购买教材、自动批量重写历史答案、自动生成题库、全量重做评分和预估分算法，以及个人资料全部改造为向量库。

本次“PDF 走大模型”限定在官方教材库导入。个人资料导入、扫描 PDF 原开关、手写识别等已有链路不因本模块自动改动。

### 3.4 核心术语

| 术语 | 定义 |
| --- | --- |
| 教材条目 | 标准书名、作者或编者、类型、别名、学科等身份信息，可有多个出版版本 |
| 出版版本 | 教材版次或讲义版本，如“第五版”“2027 备考版”；不能与同名其他作者作品混为一书 |
| 内容修订 | 同一出版版本下的后台识别、校对成果，如 r3、r4；不能拿 r4 冒充教材“第四版” |
| 原文单元 | 识别或结构化提取后、可供人工校对的正文与位置 |
| 检索片段 | 按章节及长度组织、可全文与向量检索的片段，必须回指校对后的原文单元 |
| 索引代次 | 对确定修订、切分方式、嵌入模型及维度构建的一组索引 |
| 书名匹配 | 将用户输入解析到明确的教材和允许使用的出版版本，不等同于本题有依据 |
| 答案依据 | 实际支持本次答案内容的已核验引用；不同于“召回到的所有候选段落” |
| 答案快照 | 某次生成或采用时的答案、采分点、来源、引用、配置版本及生成时间 |

## 4. 信息架构与参与角色

### 4.1 入口

- 管理后台：新增“官方教材库”，与“官方题库”并列，不藏在题库项目详情。
- 官方题库项目：原素材重复录入位置改为“关联教材与讲义”，从教材库选择已发布版本。
- APP：沿用首次“备考安排”和“我的 → 备考设置 → 参考教材”；不改底部四个 Tab。
- APP 答案：在题目详情、对应答案查看和批改结果中复用答案来源组件，点击查看相关摘录。

### 4.2 权限规则

| 角色 | 教材库权限 |
| --- | --- |
| 管理员 `admin` | 教材维护、校对、试用、发布下架、模型配置状态与任务维护 |
| 内容负责人 `content_lead` | 教材维护、校对、试用、发布下架、项目关联；不读取模型密钥 |
| 内容编辑 `content_editor` | 按现有被分配题库项目使用已关联、已发布教材辅助内容生产；首版不默认授予全库维护与发布权限 |
| 普通 APP 用户 | 填写自己的参考教材、获取自己答案的来源和相关摘录；不能读取全库原文、草稿或他人内容 |
| 其他运营角色 | 默认无教材原文维护权限，继续遵循现有角色约束 |

权限必须由后端执行，隐藏菜单不能代替鉴权。后台保留“账号名 + 时间”水印，教材维护、校对确认、发布、下架、重试、关联变更记录操作审计。

## 5. 管理后台功能需求

### 5.1 教材库列表

**FR-ADM-01 独立目录**  
支持按书名、作者、别名搜索，按教材 / 讲义、学科、状态筛选，支持分页和重置。展示教材身份、出版版本、发布状态、当前内容修订、识别或索引状态、更新时间，以及详情和检索试用入口。

同一出版版本可同时存在“线上已发布 r3”和“新草稿 r4”。列表不得因新草稿解析中而把整本书错误显示为线上不可用。筛选和统计的口径由 API 明确，不能将草稿任务数当作已发布教材数。

### 5.2 基本信息与出版版本

**FR-ADM-02 身份字段**  
维护标准书名、教材 / 讲义类型、作者或编者、适用学科、常用简称与别名；出版版本维护版次或讲义版本、出版社、出版年份、ISBN（选填）、授权说明及授权范围。讲义可补充适用院校 / 课程以避免跨范围误匹配。

书名、类型、作者或编者、适用学科、出版 / 讲义版本、授权说明为必须具备的信息。出版社、年份、ISBN 非强制；无 ISBN 的讲义可以正常录入。别名用于匹配，不代表该别名在全库唯一；冲突别名必须结合作者、学科等消歧。

**FR-ADM-03 去重与默认版本**  
新增时提示已有同名同作者条目或相同 ISBN，允许维护另一出版版本，避免重复原文。不得仅因书名相同就自动合并。每个教材身份至多设置一个面向 APP 的默认已发布版本；没有明确默认且有多个可用版次时，不自动选最新或随机版本。

**FR-ADM-04 授权与草稿**  
进入导入前记录并确认素材可用于应用内检索及相关摘录展示；发布时再次校验。授权期限等信息如已登记，过期时应停止新检索。教材草稿可以保存和编辑，但不能供 APP 使用。

### 5.3 导入原文与大模型识别

**FR-ING-01 输入方式**  
支持 PDF、DOCX、Markdown（`.md`）、TXT 和粘贴文本；同一出版版本可分册 / 分章导入，在草稿内维护顺序，避免重复拼接。首版不要求支持压缩包、电子书 DRM 或网页抓取。

文件限制、总页数、批次数、并发量和费用预算由服务端参数控制并由页面展示真实限制，不以画板中的示例页数当限制；具体数值列入第 16 节开发配置清单。

**FR-ING-02 PDF 识别方式**  
官方教材库的所有 PDF 页面统一由视觉大模型识别。可先将 PDF 渲染为页面图像，也可使用经验证支持保留页面映射的模型原生 PDF 输入；文字 PDF 不能绕过模型改用普通文本抽取作为正式识别结果，也不能静默回退传统 OCR。

原 PDF、原始页序和必要的页图保留，用于校对与定位；模型只做忠实识别和结构恢复，不补写缺页、不润色、不依据知识补全文字。输出需有结构化页面文本、标题 / 段落及不确定内容，经过 Schema 与页序完整性校验。

PDF 文件页序与纸质印刷页码分别保存。印刷页码只有在可验证识别或人工确认后才能显示；没有可信纸质页码时，使用章节标题定位，不虚构页码。后台可用“PDF 第 N 页”对照原件。

**FR-ING-03 其他格式**  
DOCX、Markdown、TXT 和粘贴文本采用结构化提取，保留正文与标题层级；Markdown 代码围栏中的 `#` 不得当作标题，不执行 HTML / 脚本。无标题正文也须保留并可校对，以“未分节内容”组织，不虚构纸质页码。

**FR-ING-04 异步任务与恢复**  
上传与识别为后台异步任务，页面可关闭后返回查看。识别进度按真实已完成页数展示；拆分、校对、索引分别展示状态，不用一个百分比伪装全部已完成。

网络、限流和服务超时可重试；重试从失败或未完成页面继续，已成功的页不重复写入或重复扣任务费用。损坏、加密、空文件、超限和无法读取的原件返回可操作的错误说明。模型漏页、顺序异常、输出不合格不得静默发布为完整内容。

上传完成、事务后入队、数据库任务状态与队列状态必须可恢复；入队失败不能遗留无入口的永久“解析中”。同一任务重复执行不得重复创建章节、片段或索引。

### 5.4 校对、切分与索引

**FR-EDIT-01 校对工作台**  
左侧目录，中间可编辑标题路径与正文，右侧为原 PDF 页图对照；非 PDF 展示可定位的原始内容。允许修正标题层级、错字、段落和顺序，展示不确定文字、未处理项和保存状态。右侧必须显示真实原件 / 原始内容，不能用模型识别结果冒充原件。

**FR-EDIT-02 校对完成**  
内容负责人或管理员需逐项处理不确定内容并确认本修订校对完成，允许确认原识别结果无误。未处理项不能用演示按钮自动清零。保存失败保留未提交内容，离开未保存页面提供保护。

**FR-IDX-01 片段与位置**  
校对文本按章节语义边界切分，长度、上下文重叠与检索数量配置化。每段保留教材、出版版本、修订、标题路径、原页 / 原文单元位置与文本校验信息。不得跨出版版本拼接段落，切分不能造成正文静默截断或丢失。

**FR-IDX-02 双索引**  
对校对后的同一份内容构建中文全文索引与向量索引，使用用户提供的嵌入模型接口完成文档向量化。查询向量必须与文档向量处于兼容的模型、维度和预处理配置，不得拿聊天模型输出文字充当向量。

**FR-IDX-03 内容变更与失效**  
修改会影响正文、章节、位置或切分的内容后，原校对完成状态和相应索引就绪状态失效；重新校对确认并构建新索引。模型、维度或切分策略变化生成新索引代次，不能覆盖线上索引后再补建。

只有结构、片段数、向量维度与数值合法性等校验通过后，才能标记就绪；向量缺失、空向量、混维度、任务部分完成不得标为完成。别名等匹配元数据变化更新匹配目录，不伪装成正文修订。

### 5.5 检索试用

**FR-TRY-01 试用输入**  
输入用户可能填写的书名、专业课 / 学科、题干和题型；试生成主观题采分点时还须输入题目分值，沿用现有合法分值校验。可选择“已发布内容（与 APP 一致）”或显式选定“当前草稿”。非就绪草稿可预览正文，但不能伪造其向量检索成功。

**FR-TRY-02 试用结果**  
展示教材匹配、采用版本、检索范围、候选段落、全文 / 向量召回信息、相关性筛选、充分 / 部分 / 无依据结论及来源位置。允许进一步生成候选答案与采分点，核对其实际使用的出处。

试用结果不直接写入 APP 用户题目，不使草稿自动发布。正式界面无“充分命中 / 无命中”的强制演示选择器；分数若展示只作为检索诊断值，不能标成答案准确率。

### 5.6 发布、修订与下架

**FR-PUB-01 发布检查**  
服务端检查身份与版本信息、授权、完整识别、校对确认、全文与向量索引就绪且与本修订一致后，才允许发布；页面按钮状态不能代替检查。索引服务不可用、校对后又修改、校验失败时不能发布。

发布使用一个可追溯的内容修订和索引代次组合，成功后原子切换可用快照，失败维持旧快照。并发发布需避免覆盖较新的人工修改。

**FR-PUB-02 线上修订保护**  
已发布正文不可原地覆盖；修改生成新草稿修订。新修订解析、校对、向量化失败时，旧修订继续对外服务。发布记录保留操作人、时间、修订、变更摘要与索引配置标识。

**FR-PUB-03 下架**  
下架先确认，停止用于新的答案检索和新的候选绑定；在最终使用片段前再次检查可用性，避免缓存或进行中的检索继续采用已下架内容。普通运营下架不自动删除已有答案及历史依据。

因授权撤销等原因要求停止展示摘录时，保留内部审计记录、限制 APP 摘录访问，展示中性“该依据暂不可查看”；不因此改写已有答案或历史评分。下架与依法处置原文分开处理，不能承诺所有历史摘录永远可见。

### 5.7 官方题库关联与运行维护

**FR-LINK-01 项目关联**  
官方题库选择已发布教材的明确出版版本，保存多对多关联。新增项目不复制教材原文；解除关联或删除题库项目不能级联删除公共教材。关联教材的修订更新按其发布快照生效，不跨出版版本自动升级。

后台编辑辅助生成答案使用项目已关联且当前可用的教材，继续走现有内容审核，不直接作为审核完成题目发布。引用需随候选、草稿和最终采用答案保留，不能只展示给编辑后丢弃。

**FR-OPS-01 维护信息**  
后台展示 PDF 识别、向量化、答案生成模型的配置状态，索引代次、任务失败阶段及重试入口；不展示密钥。向量接口缺失时可维护和识别草稿，但不能冒充完成索引 / 发布。

**FR-OPS-02 内容缺口统计**  
区分未匹配、歧义、指定版次不可用、匹配但无相关原文、部分覆盖、检索故障。后台按时间窗口汇总可用于补录或维护别名的书名与计数，不提供用户身份、题干、资料或作答原文。异常输入和疑似联系方式等不得直接变成后台公开书名统计；沿用数据最小化与访问权限。

## 6. APP 教材填写与匹配

### 6.1 填写与保存

**FR-APP-01 原入口兼容**  
首次设置与备考设置共用教材编辑组件，每门专业课最多 5 本、每本最多 64 字，沿用已有空白清理、去重、整体替换和清空规则。保留用户原始有效书名，不能用匹配结果擅自改写用户输入。

添加可输入书名，也可补作者与版次；有明确候选时可以提供可选建议。候选不是必选项，用户可直接添加自由书名。保存书名不依赖匹配、检索或模型在线；只有实际保存失败才提示失败并保留输入。

**FR-APP-02 未匹配静默**  
没有匹配、没有候选、歧义、指定版本未收录 / 不可用时，不显示“未匹配”“未收录”“多个版本请补充”“检索无结果”等提示，不显示警告图标、不弹窗、不阻塞下一步，也不展示空搜索结果说明。正常保存和展示用户填写的书名。

“可补充作者、版次”只可作为添加页的通用辅助文案，不能因匹配失败才出现。匹配明确时允许显示已匹配的标准书名、作者和实际版次；这不代表每道题均有该书依据。

### 6.2 匹配规则

**FR-MAT-01 规范化与范围**  
忽略书名号、合理空格和全半角差异；支持后台维护的别名。作者、出版版本、学科和讲义适用范围作为约束。模糊文本或向量相似度仅用于候选发现，不得单独决定书籍身份。

| 输入情况 | 自动处理 |
| --- | --- |
| 标准名 / 别名结合作者、学科可唯一确定版本 | 绑定明确出版版本；后续检索其当前已发布修订 |
| 明确写第五版，但库中只有第六版 | 不改用第六版；静默继续资料补充与通用知识生成 |
| 未写版次，同一教材只有一个可用出版版本 | 可匹配该版本，展示实际版次 |
| 未写版次，有多个版本，已设明确默认版本 | 使用默认已发布版本，展示实际版次 |
| 未写版次，有多个版本且没有默认 | 保持未确定，不随机、按最新或跨版次检索 |
| 同名不同作者、别名冲突等仍无法消歧 | 保持未确定；APP 静默，后台记录缺口 |
| 没填教材 | 跳过官方教材检索，沿用个人资料与通用知识流程 |

**FR-MAT-02 绑定与重新解析**  
用户主动点选建议形成明确版本选择；自由书名形成可重新评估的自动匹配。两者均保留输入、匹配方式和目录版本信息。显式选择不因默认版本变化切到另一版次；未指定版次的自由输入可在默认配置变更后重新解析，APP 展示实际新匹配版本。

新增教材、发布、下架、别名、默认版本或学科范围变化后，匹配缓存失效；未匹配书名应在之后使用时重新尝试，不要求用户重新填写。任何变化仅影响之后的生成，不能更换已有答案的出处。

## 7. 检索与答案生成规则

### 7.1 触发与优先级

**FR-GEN-01 覆盖入口**  
下列所有缺答案生成入口接入同一服务：导入待确认题生成、单题作答、查看参考答案、整卷练习 / 模拟考试批改所需答案，以及后台官方题目内容生产。不能只改 APP 某个页面，或保留一条仅传书名的旁路。

**FR-GEN-02 已有答案保护**  
已有导入、人工填写、用户已确认或官方审核答案继续使用，不因新增教材库自动替换；已缓存 AI 答案也不在查看、作答或批改时自动重生成。自动生成仅作用于无答案题。主动更新按第 9 节。

**FR-GEN-03 信息优先级**  
对确实需要生成的答案，先检索用户指定教材的原文；相关个人资料用于补充；仍未覆盖部分使用模型已有知识。用户已经提供的明确答案不降格为“待模型重新判断”。

多本教材只在用户指定且明确匹配的版本中共同检索，不擅自检索全库替代教材。个人资料只读取该用户当前专业课内的允许内容，不向其他用户或后台试用泄露。

### 7.2 混合检索流程

**FR-RET-01 标准流程**

1. 读取本次专业课的用户书名或后台项目的关联教材，确定允许的出版版本。
2. 取得当前可用、已发布且索引就绪的修订快照；草稿仅在有权限的后台试用中显式使用。
3. 结合完整题干、相关材料段、题型与学科提取检索信息，保留关键术语与否定条件。
4. 在限定版本内并行做中文全文召回与语义向量召回，合并去重。
5. 做相关性筛选与上下文扩展，排除同词异义、只有关键词但不能支持回答的段落。
6. 判断充分 / 部分 / 无可用依据，将有限相关原文和来源标识交给答案模型。
7. 校验答案、采分点和所用引用，记录依据快照，再保存结果与额度。

查询向量与文档向量使用兼容的嵌入配置。全文得分、向量距离、筛选结论为不同指标，不能直接相加当作概率。召回数量、融合策略、相关性阈值、片段长度与生成上下文预算须用评测确定并版本化，不能只沿用现有字面重合阈值即宣称完成语义检索。

**FR-RET-02 可用性二次过滤**  
索引召回时按教材、版次、发布修订、权限与索引代次过滤，交给生成模型前再次校验状态。过期缓存或索引中的草稿、已下架、失效授权内容不得用于新答案。不能在全库检索后只靠提示词要求模型忽略其他书籍。

生成结果保存前再次检查下架和授权状态；若生成期间该来源被禁止用于新答案，不能保留其答案内容后仅删除引用标签，应重新生成不使用该来源的答案或返回可重试失败。正常新修订发布不等同于原修订被下架，已开始的生成可以按已锁定的合法快照完成并记录该修订。

### 7.3 充分、部分与无依据

| 情况 | 答案处理 | APP 来源 |
| --- | --- | --- |
| 教材原文足以支持本题主要答案 | 按原文术语组织答案 | 依据教材生成 |
| 教材与个人资料共同覆盖答案，没有通用知识扩展 | 分别记录两类原文及其支持部分 | 教材 + 个人资料依据 |
| 教材覆盖部分，仍需模型通用知识补充，可同时采用个人资料 | 记录原文支持部分和模型补充部分 | 教材依据 + AI 补充；有个人资料时同时列来源 |
| 教材无可用依据，个人资料足够 | 按个人原文生成 | 依据个人资料生成 |
| 只有个人资料部分依据，其余模型补充 | 保留个人来源和补充说明 | 个人资料依据 + AI 补充 |
| 没有任何可采用原文 | 根据通行知识生成 | AI 通用知识生成 |
| 教材 / 个人资料观点明显冲突 | 分别保存来源与差异，提示相关观点需核对；仍为待确认 | 显示已采用来源与“观点存在差异，请核对” |

“充分”指有可核对依据支持主要答题内容，不表示对答案准确率的保证。只有教材书名、模型声称“熟悉教材”、关键词相似或候选召回，都不算教材依据。

原文来源集合与“是否有通用知识扩展”分别保存、分别校验，再决定标签。“AI 补充”指新增原文未支撑的答题内容，不指大模型对原文做分点、概括等组织动作。全部内容均有教材与个人原文支撑时，不显示“AI 补充”。

不能为了满足“教材优先”而强行采用无关原文。未覆盖时允许继续使用书名作为表达偏好，但必须明确模型未获得该书原文，不输出虚构引文、页码或“依据教材生成”标签。

### 7.4 引用与输出校验

**FR-CIT-01 结构化输出**  
模型输出答案、采分点、实际使用的来源片段标识及支持内容；引用只能使用本次输入中提供的合法标识。书名、作者、版次、修订、位置等由服务端从权威元数据填充，不能接受模型自由编造这些字段。

**FR-CIT-02 引用真实性**  
服务端验证标识属于本次允许的检索集合、片段文本与修订一致、引文为原文可定位子串、位置存在，并核对引用是否实际支持被标注内容。不能只验证 ID 存在就认定观点有出处，也不能把全部召回段落保存为已采用依据。

非法引用、题型错误、空答案、采分点关键词与答案不符、分值不合法等，按现有 AI 输出校验机制修复 / 重试。修复仍不合格时丢弃不可信依据，重新生成正确来源分类的答案或返回生成失败；不保留错误教材标签。

主观题采分点分值合计等于题目分值，沿用现有规则；客观题不强行生成主观采分点。引入教材库不改变客观 / 主观判分边界。

**FR-CIT-03 文本与指令边界**  
教材原文和个人资料只作为数据。文中出现的“忽略系统要求”等不得作为工具、权限或生成流程指令执行。原件、识别文本、模型输出的显示均按现有内容安全和转义规则处理。

### 7.5 故障与静默降级

**FR-RET-03 故障分类**  
未匹配、无相关片段与接口故障分别记录，不把超时记为教材未收录。检索按有限超时与重试预算执行，不无限阻塞作答或整卷任务。

向量分支暂时失败时，可使用经过同样相关性校验的全文结果；全文分支失败时，可使用合法向量结果。剩余来源不足则继续个人资料 / 通用知识生成，APP 不展示教材库故障或未匹配提示，但来源标签必须符合实际使用情况。

模型生成最终失败、网络导致答案保存失败、额度不足等真实操作失败，使用现有明确错误与重试流程。这与“书名未匹配静默”不同；不能虚假提示保存成功。

## 8. APP 答案展示与视觉规范

### 8.1 来源和出处

**FR-UI-01 本次实际依据**  
答案仍标“AI 参考答案 · 待确认”。来源组件按第 7.3 节展示真实类型；即使命中教材，也不自动标“官方标准答案”或改为用户已确认。确认前不计预估分等规则保持现有 PRD。

展示教材标准名、作者 / 版次、章节标题和“查看依据摘录”。只读取该次生成快照，禁止根据当前专业课书名临时拼接“参考了你的教材”。个人资料来源复用原文定位组件，严格校验用户归属。

**FR-UI-02 相关摘录**  
使用底部弹层展示本题相关摘录、实际出版版本与标题路径。只有可靠纸质页码才展示纸质页码，无页码正常展示标题。允许区分摘录与模型组织后的答案，不能把答案复述伪装成原文。

不暴露整本原件 URL、全库段落查询接口或整本下载按钮；用户只能通过自己有权访问的答案查看其引用。普通修订更新后，历史摘录仍按快照定位，受下架 / 授权展示策略约束。

**FR-UI-03 静默与透明的边界**  
未匹配不提示；“AI 通用知识生成”作为正常来源标签保留。不得追加“因为你的教材未收录”等解释。实际存在内容冲突可以提示观点核对，但不能借此提示匹配失败。

### 8.2 状态与可访问性

**FR-UI-04 视觉约束**

- APP 基准 390×844，页面边距 22；页面标题 26、弹层标题 20、卡片标题 17、正文 15、辅助 13、注释 12。
- 中文系统字体，数字 / 英文使用项目已打包 DM Sans，不运行时请求 Google Fonts。
- 使用现有 `packages/ui-tokens` 的墨黑、白、灰、类别色和状态色；VI 品牌色不扩展到业务页面。
- 主按钮高 50、胶囊圆角；输入、卡片、列表和底部弹层按现有组件与设计稿实现。
- 可点击范围至少 44×44，系统字体 1.3 倍无截断关键动作、横向溢出或重叠；长文可滚动，底部操作不盖住末行。
- 后台沿用现有后台主题、表格、表单、弹窗与水印规范。

**FR-UI-05 完整状态**  
处理超过 300ms 的加载、空教材列表、正常保存、保存失败、生成中、超过 15 秒的安抚文案、生成失败、额度不足、出处加载失败和权限受限。按已确认设计支持“稍后回来查看”：生成状态和结果必须持久化，离开页面或重启 APP 后可恢复，不能通过删除文案代替这项能力，也不能依赖浏览器 / APP 页面存活完成任务。

APP 检索无结果不是一个空状态页面。正常继续生成，按实际来源显示答案。用户离开或重试时不能重复扣次、丢失旧答案或现有作答草稿。

## 9. 答案保存、主动更新与历史保护

**FR-ANS-01 保存快照**  
生成结果保存答案、采分点、生成时间、来源类型、采用的书籍 / 版本 / 修订 / 索引代次、有效引用及支持片段、提示词 / 模型配置版本。原文引用有稳定标识和必要摘录快照；不能只保存一个会漂移的“当前教材 ID”。

导入待确认条目也须保存依据；确认入库后原样转入正式题目。官方内容生成候选经编辑修改后，引用不得仍声称支持已删改的内容；需重新核对或去掉失效来源。

**FR-ANS-02 主动更新范围**  
对尚未确认的 AI 答案提供“按当前教材重新生成”。已有人工 / 导入 / 用户已确认 / 官方审核答案不显示自动替换入口。本次不增加已确认答案的一键重写流程。

新结果先保存为候选，用户比较原 / 新答案、采分点和来源后选择“保留原答案”或“采用新答案”；未采用前，原答案及后续批改依据不变。失败、退出或拒绝候选均不覆盖原答案。采用后，新答案与采分点仍待确认。

**FR-ANS-03 并发采用**  
采用时检查原答案版本。如果候选生成期间用户已编辑、确认或更新该题，不能覆盖较新内容；刷新并提示真实内容冲突，不能静默丢弃用户修改。候选、采用和额度均支持幂等。

采用时也检查候选所用来源的下架与授权状态。普通下架或授权失效发生在候选生成后、采用前时，该候选不可写为新的当前答案；保留原答案，允许重新生成。APP 使用“这份候选暂不可采用，请重新生成”的中性说明，不暴露教材匹配缺口。正常修订更替不使旧修订候选失效；已采用的历史答案按 FR-PUB-03 的展示策略处理，不被自动覆盖。

**FR-ANS-04 历史批改**  
每次批改继续使用其答案与采分点快照。教材更新、下架、书名更改、答案重新生成与采用都不重写已完成批改、作答、整卷报告或历史预估分。运行中的批改不得逐题漂移到不同版本而缺少记录；使用的依据需可追溯。

### 9.1 额度与成本

- 书名匹配、全文 / 向量检索不单独扣用户次数。
- 首次单题缺答案生成、整卷批改中的生成继续沿用现有额度规则；相同请求重试不重复扣。
- 主动重新生成沿用单题 AI 生成额度类型，不增加检索收费。候选成功生成并可查看时扣一次，采用不再扣；生成失败不扣，放弃已成功候选不退次。此口径已由用户确认。
- 同一候选只能扣一次；生成失败不扣，采用 / 放弃不能产生重复扣次。点击重新生成前展示已确认的额度说明，不能操作后突然改变收费口径。后台试用、识别和索引成本计运营侧，不扣 APP 用户额度。
- 并发首次生成、队列恢复、结果已写入但响应丢失等场景，以幂等和事务保证只扣实际约定次数。

## 10. 数据与状态要求

本节定义必须表达的数据能力，不强制最终表名、字段名或向量数据库产品；具体 SQL 和 API 由技术方案按契约先行落实。

| 数据实体 | 至少需要保存的内容 |
| --- | --- |
| 教材身份 | 稳定 ID、标准书名、类型、作者 / 编者、学科、别名与适用范围 |
| 出版版本 | 稳定 ID、版次 / 讲义版本、出版社 / 年份 / ISBN、默认配置、授权与可用状态 |
| 内容修订 | 出版版本 ID、修订号、原件、正文快照、识别与校对状态、确认人 / 时间、校验标识 |
| 章节与原文 | 标题树、原文单元、顺序、PDF 页序、可信印刷页码、不确定内容及处理记录 |
| 检索片段 | 修订、片段 ID、标题路径、源位置、文本、切分配置与内容校验 |
| 索引代次 | 修订与校验标识、全文状态、嵌入服务 / 模型版本 / 维度、预处理配置、向量状态、任务状态 |
| 任务记录 | 阶段、输入版本、真实进度、失败码、重试数、幂等键、取消 / 恢复与耗时 |
| 用户教材配置 | 用户与专业课归属、原书名、显式 / 自动选择、匹配版本、匹配目录版本 |
| 项目关联 | 项目和明确出版版本的多对多关系，不拥有公共原件 |
| 答案生成 / 候选 | 题目或导入条目归属、答案及采分点版本、来源、引用快照、额度幂等与候选状态 |
| 审计与聚合 | 内容管理审计；最小化、脱离用户身份的书名缺口和检索结果统计 |

### 10.1 状态分层

| 层级 | 状态表达 |
| --- | --- |
| 版本对外状态 | 未发布、已发布、已下架 / 授权不可用；指向当前有效修订 |
| 草稿任务 | 上传中、待识别、识别中、识别失败、待校对、已校对 |
| 索引任务 | 待构建、构建中、失败、就绪、内容变更已失效 |
| 答案候选 | 生成中、失败、待比较、已采用、已放弃、因原答案变更不可采用 |

状态必须由真实结果驱动。部分页面处理成功不等于整本成功；校对完成不等于索引就绪；索引就绪不等于已发布。已发布修订保持不可变，新修订的任何错误不覆盖旧的线上可用状态。

## 12. 旧数据迁移与兼容

**FR-MIG-01 旧素材迁移**  
迁移现有 `official_references` 与段落至新身份 / 出版版本 / 内容修订体系，保留旧 ID 映射、项目关系和原始标题。无法证明同书同版本的重复项不自动合并；保留人工核对入口。

旧素材缺作者、版次、授权范围、原页、校对或向量索引时，标为待补全 / 草稿，不自动供 APP 检索。原有后台项目内容生产在切换前保持可用，切换后缺项通过明确维护流程补齐；不以“迁移完成”宣称向量索引完成。

**FR-MIG-02 用户书名**  
已有 `subjects.textbooks` 原列表保持完整，可后台逐步匹配或使用时惰性匹配；不得清空无法匹配的书名，不发未匹配通知。

**FR-MIG-03 旧答案**  
不为旧答案根据现行教材设置补造出处，不反推旧模型使用过哪个教材。缺少真实来源记录的历史 AI 答案使用中性“AI 参考答案 / 历史生成记录”说明，不错误归为已核实教材引用，也不强行判断为通用知识。

**FR-MIG-04 非破坏迁移**  
新增 goose 迁移、增量回填、核对数量和映射，再切换读写；不修改已合并迁移。旧项目删除不得继续级联删除已经迁为共享的教材。回滚关闭新链路时，原书名、答案、历史批改和旧接口可继续使用。

## 13. 非功能与安全要求

### 13.1 模型接入与成本

- PDF 使用现有允许的视觉模型链路；沿用项目当前模型偏好，最终以服务端配置和真实 PDF 评测为准，不能仅凭模型名称认定支持。
- 嵌入模型由用户提供的调用服务接入，独立于答案生成模型，支持文档和查询嵌入，记录版本与维度；具体协议按真实服务适配。
- 配置入口、密钥、价格和额度由服务端管理；客户端不持有密钥，后台不回显密钥。无真实配置时使用 mock 联调，禁止将 mock 指标当上线效果。
- 大文件分批识别、文档嵌入批处理、限流与重试、用量统计；失败费用与成功任务去重分别记录，不承诺供应商不会对失败请求计费。

### 13.2 性能与恢复

- 目录 / 书名查询与答案生成解耦；长文件识别和索引必须后台异步。
- 检索与模型预算不得超过客户端和 Worker 的整体超时；本次生成必须具备持久任务 / 结果恢复能力，按既有同步入口的兼容要求补充任务查询与轮询，不能仅延长页面等待。
- 记录匹配、全文 / 向量、筛选、生成各阶段耗时与故障；量化 P50 / P95 和并发上限，用评测确定上线配置。无真实环境压测前不宣称满足固定时延。
- 同题并发请求不重复生成采用结果或扣次；索引 / 发布切换后缓存有版本标识并失效，不能混用多代正文与向量。

### 13.3 数据访问

- 私有原件沿用 OSS 私有访问，后台短期授权读取；APP 无整本访问权限。
- 所有用户题目、原书名配置、候选与摘录接口校验归属；用他人 ID 返回现有约定的 404。
- 普通后台不能通过检索试用读取个人题目、资料与作答；个人上下文只在用户自己的答案链路使用。
- 运行日志不记录题干、资料 / 教材全文、作答原文和密钥；可记录任务、阶段、来源标识、数量和错误码。
- 题目或账号删除沿用现有用户数据删除流程，处理其候选与个人引用快照；不得删除共享教材及其他用户记录。

### 13.4 发布开关

教材库后台维护、APP 官方教材检索应有独立控制能力，不依赖“官方题库上线”开关；官方题库关闭时，自建题库仍可在灰度开放教材检索。关闭新检索时 APP 继续正常填书名与使用原有答案；新答案按可用个人资料 / 通用知识流程生成，不能虚称教材引用。

索引配置变化、识别失败率或引用异常可暂停发布 / 新检索，不能影响已保存的作答与历史报告。

## 15. 验收标准

### 15.1 功能验收矩阵

下列用例均为必须覆盖的发布检查，自动化与人工验证结合；最终记录实际结果，不能用“已画设计稿”代替实现验收。

| 用例 | 场景与通过条件 |
| --- | --- |

| AC-12 | DOCX / MD / TXT / 粘贴内容保留标题与正文，无标题、长段落和代码围栏正常处理 |

### 15.2 AI、检索与真实模型评测

建立分层评测集：PDF 识别、书名匹配、检索召回、相关性与无依据拒用、引用支持、答案 / 采分点。样本覆盖文字 / 扫描 / 混合 PDF、标题跨页、模糊文字、同名作者、版次冲突、简称、语义改写、同词异义、多书冲突与无答案题。

输出页完整率、文字 / 结构识别质量、书名误绑定率、Recall@K、可用依据精确度、无依据误标率、引用可定位与支持率、答案质量、时延和用量。具体性能与质量数值门槛须结合用户提供的真实服务在开发技术方案中登记；未确定前不编造已达标数字。

自动化覆盖 API 契约、数据库状态转换、任务幂等、故障注入、并发发布 / 采用、越权和 UI 关键流程。真机核验首次设置、教材编辑、出处弹层、字体放大和作答回退；用真实模型与已获授权 PDF 完成识别到答案的闭环验收。
