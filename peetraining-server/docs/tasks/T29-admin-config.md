# T29 管理后台：配置与系统

- 仓库：后端 + 前端（先后端，后前端）
- 依赖：T28
- 计划完成：10/11
- 状态：审查中（生产待验证）

## 目标

不改代码就能调额度、价格、协议、开关和 AI 版本。

## 范围 · 后端部分（在 peetraining-server 里做，先合并并打契约标签）

- 7.8：AI 任务列表、成本统计、提示词版本灰度（比例、对比指标、回滚）；免费额度与会员价格；协议正文与版本；初试日期；功能开关；App 版本；规则参数
- 7.9：系统消息开关与时间；手动公告（对象、渠道、定时）
- 7.15：后台账号与角色、操作日志

## 范围 · 前端部分（在 peetraining-web 里做，先执行 pnpm gen:api）

- 7.8 AI 与额度、7.9 消息与公告、7.15 后台账号与权限

## 记录（开发中填写）

- 实现要点：
  - 7.8 规则参数（额度、价格、奖励、AI 预算、规则）：通用编辑，新值的结构必须与原来一致（只能改数值、开关、文字；额度可设「不限」），再整体过 rules.ParseParams；带版本号防覆盖；保存后立即让 API 进程的参数与开关缓存失效（Worker 最多 30 秒）
  - 7.8 协议：草稿 → 发布；已发布的不能改；发布后老用户启动时 /bootstrap 返回待确认（0.4b），消息中心「协议更新」由 T27 的定时任务发
  - 7.8 初试日期、功能开关（全部 / 指定用户，最多 200 个）、App 最新与最低版本（校验版本号与 https 下载地址）
  - 7.8 AI：近 7 天按能力与「模型 @ 提示词版本」统计调用、成功率、单次成本、耗时与成本占比；每活跃用户每天成本对比预算（rule_params.ai_budget）、本月成本占收入；灰度设置只能选 prompts 里已有的版本，支持扩大比例、全量、回滚
  - 7.9 系统消息：rule_params.system_messages 控制复习到期（开关与北京时间整点，定时任务改为每小时检查）与解析 / 批改 / 导出完成消息；手动公告（全部或指定用户、定时、取消未发）
  - 7.15 后台账号：添加成员（初始密码，首次登录必须改）、改角色与停用（清掉会话，立即按新权限）、重置密码；不能停用自己或去掉自己的管理员角色；操作日志
  - 契约 api-v0.16；迁移 00017（ai_budget、system_messages）
  - 前端：7.8 分 8 个标签页（AI 成本与灰度、免费额度与会员权益、价格与奖励、协议、初试日期、功能开关、App 版本、规则参数），参数编辑器把 JSON 展开逐项编辑；7.9、7.15
  - 新增依赖：dayjs（antd 日期控件的值类型，原为 antd 的间接依赖）
- 偏离计划的地方与原因：
  - 灰度对比指标先给成功率、单次成本、耗时；异议率与人工抽检一致率按提示词版本拆分要等批改记录里存版本号后再加（T31 评测时一起做）
  - 公告「弹窗」只记录勾选，App 端目前只在协议更新时弹 0.4b（D39）
- 需要手动验证的步骤：
  - 后台把免费批改次数从 3 改成 5，App 刷新额度条立即显示 5 次
  - 新建并发布一版隐私政策，老账号重新打开 App 看到 0.4b
  - 对自己的账号打开某个开关，App 重启后出现对应入口
