## 记录（开发中填写）

- 实现要点：
  - internal/notify：消息列表（30 天内、游标分页）、未读数、标已读、全部已读；跳转目标统一为 link {page, params}
  - 补齐消息类型：题库整理完成 / 解析失败、需核对（importer 收尾时）、导出完成；整卷、作文批改完成与会员类已有；dedupe_key 按事件去重，任务重试不重复发
  - 定时任务：清理 30 天前的消息（每天 03:41）、发送到点的后台公告（每 5 分钟，全部用户或指定用户）、协议更新（每小时，30 天内发布的新版本给未同意的用户）、复习到期（每天 07:05，打开了复习到期提醒且有到期知识点或错题的用户）
  - 授权查看：notify.RecordAccess 校验授权在有效期内、对象在授权范围内，写 content_access_logs 并给用户发「客服查看了你授权的资料」；后台 7.6、7.7 的查看接口（T28）先调它再读内容
  - 客服回复：notify.Reply 写回反馈并发到消息中心（后台入口在 T28）
  - 契约 api-v0.14：GET /messages、GET /messages/unread-count、POST /messages/{id}/read、POST /messages/read-all
  - 前端：2.3 消息中心（今天 / 更早分组、点击跳转并标已读、全部已读、空状态、保留 30 天说明）；今日首页铃铛与红点（每分钟刷新未读数）；本地学习提醒（expo-notifications 每天按备考设置的提醒时间提醒，关闭每日训练提醒时取消）
- 偏离计划的地方与原因：
  - 单题主观题批改是同步返回结果的，不发「批改完成」；整卷与作文批改是异步的，完成时发
  - 复习到期提醒走消息中心 + 本地学习提醒，不做服务端推送（没有接厂商推送通道，D36）
- 需要手动验证的步骤：
  - 真机：在 6.10 设置提醒时间，确认到点收到本地通知；关闭「每日训练提醒」后不再收到
  - 导入一份资料，离开 App，回来后首页铃铛有红点，消息点开跳到核对页
  - T28 完成后：后台在授权期内查看反馈资料，用户消息中心收到通知
