## 记录（开发中填写）

- 实现要点：
  - 官方内容存在 source = official、没有 owner 的题库里；用户添加时复制到自己那门课的题库（origin / source = official，official_kp_id / official_question_id 指回官方条目），刷题、批改、复习、数据隔离都不用改（11.15）
  - 每次发布或回滚后对每个订阅用户做一次对账（幂等）：新增的复制过去，知识点标「新」两周；没改过的（副本哈希等于上次同步记下的 official_hash）跟着更新，id 不变，掌握度与作答记录保留，采分点有实质变化时背诵重新进入复习；改过的不覆盖，发「官方内容已更新」；下线的题目归档
  - 同名知识点合并：只记对应关系，保留用户自己的表述和采分点（同名有多个时合并到有原文表述的那个）；移除官方题库时没改过的副本连同练习记录删除，改过的保留为用户自己的，合并的解除对应
  - 7.10 需求洞察：按专业课代码统计自建用户、人均题量、近 7 天新增、填了目标院校、付费率、人均待复习，只有计数；立项、标为未规划
  - 7.11 立项（同时建官方题库）、分配编辑、授权资料清单（须注明已获授权或公开真题）、阶段进度；内容编辑只能访问被分配的项目
  - 7.12 AI 从资料原文拆知识点（复用导入引擎的 ExtractKPs），按名称与现有知识点树对齐：新增 / 补充来源 / 表述差异；录题时 AI 从参考答案提采分点（ExtractRubric）；草稿支持新增、修订、下线（题目）
  - 7.13 新编辑前 3 次提交全量审核，之后 30% 抽检，没抽中的直接通过（记 skipped）；通过、退回（必须填原因）、修改后通过；不能审核自己提交的
  - 7.14 发布预览（变更清单标出采分点有变化的、自动检查、通知预览）；发布时先应用知识点再应用题目，应用后再查一次结构（知识点都有采分点、没有空的板块与章节），记版本与回滚快照；通知只发给订阅用户；首次上线提醒自建了同一专业课、能看到开关的用户（5.6）；只能回滚最新版本
  - App 侧接口受 official_bank 开关控制（关闭时 404）；后台接口不受开关影响，内容团队可以先做好再开
  - 契约 api-v0.17（KnowledgeNode 加 is_new；顺带修正知识点树没把 official 返回给 App 的问题，并改为按 origin 判断，合并的知识点仍算用户自己的）；迁移 00018
  - 前端：后台 7.10–7.14 五个页面；App 题库页「添加官方题库」入口（开关打开时）、添加 / 移除页、知识点树的「官方」「新」标记、消息跳转
  - 验收测试 internal/practice/official_integration_test.go：立项 → 生产 → 审核 → 发布 → 用户添加 → 两边题都能练 → 发布新版本后掌握度保留 → 回滚 → 移除
- 偏离计划的地方与原因：
  - 知识点的合并、拆分与下线、官方模拟卷、考情画像暂不做，发布检查里的「模拟卷结构」随官方模拟卷一起加（D40）
  - 立项门槛先在页面上写死 30 人，只作提示
- 需要手动验证的步骤：
  - 后台建 content_lead 与 content_editor 两个账号，用测试资料走一遍立项 → 生产 → 审核 → 发布
  - 对自己的账号打开 official_bank，App 题库页添加官方题库，练一道官方题；后台发布新版本后看知识点「新」标记与消息
