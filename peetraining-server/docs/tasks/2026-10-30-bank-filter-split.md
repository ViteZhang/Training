# 题库答案筛选与知识点拆分修复

用户反馈：答案状态参数被静默忽略；拆分把所有题目复制给每个新知识点，并丢失掌握度。

- 正式参数 `answer_status=material|confirmed|ai|missing`，App 已使用此参数。现有正式筛选链路存在，未知参数名默认忽略；为题目列表增加未知、重复、空参数校验，返回400，领域服务拒绝非法状态值。筛选发生在分页前，facets仍为整库统计。
- 修正列表空白答案判断，将只有空格、制表符、换行的答案归为缺答案，与答案档位规则一致。
- 新增 `GET /knowledge-points/{kpId}/split-questions`，列出全部原关联（含非主关联、历史题），避免卡片20条上限截断。
- 拆分parts新增可选 `question_ids`。有关联题目时必须提供完整互斥的分配；旧App未提供分配时返回400，保留原节点。无题目时旧请求仍可用。
- 分配验证、题目迁移、掌握度复制、删除原节点与真题计数更新在同一事务内；锁定原节点和关联防止并发拆分。保留题目的主次关联以及其他知识点关联。
- 每个新点继承原掌握分、状态、自评、作答/浏览标记、正确日期、复习与背诵排期及衰减日期；不会重置未学。题目原作答和批改记录保持原题ID。
- 题目按知识点筛选同时匹配非主关联，避免拆分后漏题；App操作后刷新知识点和题目详情缓存。

无需数据库迁移。本次只修改代码与隔离测试数据，不修写生产数据。App拆分交互需要更新客户端。

验收：
1. 请求正式答案参数missing/ai，逐页只出现对应答案状态；四档合计覆盖全部题目。facets为整库数量，不表示当前返回数量。
2. 请求answerStatus、answer_state、未知枚举、重复或空参数，均应400，不得返回全部题目。
3. 拆分超过20题的知识点，全部题目可分配，未分完按钮不可用；每题只能选一个新点。
4. 分配完成拆分，两点题目总数等于原数、无复制；原本其他知识点的关联仍在，主次标记保留。
5. 原节点已学习时，两个新点保留原掌握分、状态和复习日期。
6. 旧版缺分配、漏题、重复分配、无关题、他人题、空名称失败后，原节点与关联保持完整。

验证结果：48题四档答案状态HTTP分页通过；25题拆为12/13、非主关联、全部掌握度字段与排期继承、漏分/重复/他人题/旧请求/空名称回滚、跨用户404通过（真实隔离MySQL/Redis，-race）。App题库12项测试、前端typecheck/lint、后端go test -short -race ./...、go vet、增量golangci-lint通过。

题库全量集成中 TestRepairExamInfoKeepsUnconfirmedSource 失败（unconfirmed=6 with_year=5）；在未修改的3aa13fd上同样复现，属于既存真题年份修复问题，本次未改动其逻辑。未做生产测试及真机测试。
