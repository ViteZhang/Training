# T06 账号：登录、协议、设备与注销

- 仓库：后端 + 前端（先后端，后前端）
- 依赖：T03
- 计划完成：10/7
- 状态：审查中

## 目标

用户能用手机号登录，协议、权限、版本更新、注销都按 PRD 走。

## 范围 · 后端部分（在 peetraining-server 里做，先合并并打契约标签）

- 短信验证码：6 位、5 分钟有效、60 秒一次、每天 10 次、错 5 次失效（Redis 计数）
- 登录即注册；访问令牌 + 按设备的刷新令牌；设备列表与移除
- 协议版本：后台配置正文与版本，记录用户同意的版本，有新版本时启动接口返回需重新同意
- 版本检查接口：最新版本、最低版本、下载地址
- 注销：申请后 7 天冷静期，期间登录即撤销；到期由定时任务删除账号、资料原件（含 OSS）、题目与作答
- 更换手机号（新旧号码都验证）

## 范围 · 前端部分（在 peetraining-web 里做，先执行 pnpm gen:api）

- 模块 0 全部 13 页：0.1–0.6b（设计稿 m0_*）
- 6.11 账号与安全、6.12 注销账号
- 短信自动填充；权限说明弹层只在首次使用对应功能时出现

## 参考

- docs/prd.md 第 6 节模块 0、第 9 节 6.11–6.12
- docs/design/INDEX.md 模块 0

## 验收

- 真机走通：输入手机号 → 收验证码 → 登录 → 新用户进 1.1，老用户进 2.1
- 验证码错误、过期、频率限制、协议未勾选、协议更新、强制更新各状态与设计稿一致
- 注销后 7 天内登录可撤销；到期后数据库与 OSS 中该用户内容全部删除（集成测试覆盖）

## 记录（开发中填写）

- 实现要点：
  - 后端 internal/auth：验证码 6 位、5 分钟有效、60 秒一次、每天 10 次、错 5 次失效（Redis 计数，验证成功即作废），另加同一 IP 每小时 30 条防刷；登录即注册，登录时记录同意的当前协议版本；访问令牌 JWT（30 分钟）+ 按设备的刷新令牌（60 天，只存哈希，每次刷新轮换，已作废的令牌被复用时作废该设备全部令牌）；设备列表与移除；更换手机号（新旧号码分别验证）；注销进入 7 天冷静期并退出全部设备，冷静期内登录即撤销，到期由定时任务先删 OSS 前缀 u/{userID}/ 再删账号（外键级联）
  - 协议版本：登录同意当前版本，发布新版本后启动接口返回需重新同意的列表（会员服务协议不在启动时弹出）；版本检查返回最新版本、最低版本、下载地址，低于最低版本强制更新
  - 按契约校验请求（参数、请求体、鉴权），鉴权方式跟随 openapi.yaml 每个接口的 security，新接口不用改中间件
  - App：0.1 启动页按 /bootstrap 分流（强制更新 0.6b、普通更新每版本提示一次 0.6、协议更新 0.4b、登录与引导进度）；0.2 / 0.2a / 0.2b 登录（3-4-4 分隔、号码校验、协议默认不勾选、未同意弹层与高亮）；0.3 / 0.3b / 0.3c 验证码（6 格、短信自动填充、输满自动登录、错误清空并提示剩余次数、倒计时重发、收不到验证码弹层）；0.4 协议两个 Tab；0.5 / 0.5b 权限说明与被拒的通用 Hook（相机、相册、麦克风、通知文案，T12、T18 接入具体权限）；6.11 账号与安全；6.12 注销；Tab 页未登录时回登录页
- 偏离计划的地方与原因：
  - 处理器把 *gin.Context 当 context 传给数据库会产生数据竞争（-race 测出），统一改为 c.Request.Context()，写进 CLAUDE.md「踩过的坑」
  - 协议正文需要法务提供（设计稿标「正文由法务提供」），后台配置协议在 T29；在那之前 /agreements 返回 404，0.4 页显示错误状态
  - 0.5 权限说明做成通用 Hook，真正申请相机、相册权限的库在 T12 引入
- 需要手动验证的步骤：
  - 阿里云短信签名与模板就绪后，在生产 .env 设置 SMS_PROVIDER=aliyun 并接入真实短信（本卡只有 mock，真实短信实现见下一步记录）
  - 真机：输入手机号 → 收验证码（iOS / 安卓短信自动填充）→ 登录 → 新用户进 1.1，老用户进 2.1
  - 后台发布新协议版本后（T29），老用户启动看到 0.4b；把最低版本调高后看到 0.6b 且无法关闭

  - [x] 注销后 7 天内登录可撤销；到期后数据库与 OSS 中该用户内容全部删除（集成测试 TestDeletionCoolingAndPurge）
