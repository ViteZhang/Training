# T14 考情分析、知识图谱、作文知识库

- 仓库：后端 + 前端（先后端，后前端）
- 依赖：T10、T11
- 计划完成：10/10
- 状态：审查中

## 目标

用用户自己的真题告诉他这门课怎么考。

## 范围 · 后端部分（在 peetraining-server 里做，先合并并打契约标签）

- 考情统计按 PRD v3 11.11：题型结构与建议用时、板块分值占比、高频考点、缺资料提醒、出题风格标签（AI）
- 知识关联：AI 按章节和同题出现生成关联，用户可调整
- 作文知识库接口：写作方法、素材、范文

## 范围 · 前端部分（在 peetraining-web 里做，先执行 pnpm gen:api）

- 3.8 考情分析、3.9 知识图谱（可缩放、点节点、筛选）、3.10 作文知识库

## 参考

- docs/prd.md 第 7 节 3.8–3.10、第 11.9 节、第 11.11 节
- docs/design/pages/m3_profile、m3_graph、m3_essaykb

## 验收

- 只有 1 套真题时提示再导入；2 套以上显示统计，数字与手工计算一致（单元测试）
- 图谱在 200 个节点内流畅缩放

## 不做

- 卡片范围以外的页面、接口和重构；发现需要的，记到 docs/open-questions.md

## 记录（开发中填写）

- 实现要点：
  - 契约 v0.2.0（只加不改）：getExamProfile、getKnowledgeGraph、createKnowledgeRelation、deleteKnowledgeRelation、getEssayKnowledgeBase、setEssayMaterialFavorite
  - 考情分析：数字全部来自 rules.BuildExamProfile（题型结构、近 N 年未变 / 变化年份、板块分值占比、高频考点）、rules.SuggestedTimes（建议用时，与选择模式、时间报告同一套）、rules.MissingMaterialSections（缺资料提醒）；不足 2 套真题 ready=false；依据的资料与未计入题数；出题风格标签（exam_style，按真题内容哈希缓存，失败为空不影响统计）
  - 知识图谱：第一次打开生成关联并记录时间（只生成一次，用户删光后不再生成）：同章相邻知识点「同章并列」、同一道题的知识点「相关」、AI（kp_relate）找「易混对比」；筛选全部 / 薄弱（掌握分 < 40）/ 真题考过、按板块；最多 200 个节点；卡片里增删关联（两端须在同一题库）
  - 作文知识库：写作方法（掌握状态、对应维度、出处）、素材（收藏在前、AI 补充单独标）、范文（按作文题归类、结构拆解）、作文题（年份、要求字数、范文数）、当前评分标准（无用户细则时为通用五维度）
  - App：3.8 考情分析（不足 2 套时引导导入）、3.9 知识图谱（react-native-svg 绘制，确定性力导向布局一次算完，＋／－缩放与双向滚动，点节点看摘要、关联与删除、进卡片）、3.10 作文知识库（作文课的题库页显示为 3.10：知识库 / 作文题 / 资料）、知识点卡片「添加关联」
  - 修复（T10 引入）：导入时同一道题在不同年份的真题里各算一次；题库去重时不同年份的真题不标「疑似重复」
- 偏离计划的地方与原因：
  - 缩放用按钮而不是双指手势：react-native-gesture-handler / reanimated 还没作为依赖接入，先保证功能可用；之后需要时再换
  - 「刷一组高频考点」在训练模块（T17）接通，先提示
- 需要手动验证的步骤：
  - 真机打开 150–200 个节点的图谱，缩放、滚动、点节点是否流畅
  - 导入 2 套以上真题后核对考情分析的题型结构与板块占比
