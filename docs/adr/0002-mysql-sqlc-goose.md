# 0002 MySQL 8 自建在 Docker 里，用 sqlc 和 goose

- 日期：2026-10-01
- 状态：已采纳

## 背景

数据以关系型为主（用户、题库、作答、额度台账），需要事务保证「扣额度与写结果」一致；预算有限，只有两台服务器。

## 决定

- MySQL 8（InnoDB、utf8mb4、utf8mb4_0900_ai_ci），自建在数据库机的 Docker 里，数据放独立数据盘
- 连接强制 parseTime、会话时区 UTC：数据库时间一律存 UTC 的 DATETIME(3)，业务日期在应用层按 Asia/Shanghai 换算
- 查询用 sqlc 从 SQL 生成类型安全的代码（T03 接入），不用 ORM
- 迁移用 goose，SQL 文件顺序编号、内嵌进二进制；发布时由 `api migrate up` 执行；已合并的迁移不修改，字段只加不删
- 集成测试用 testcontainers 起真实 MySQL，每个测试独占一个数据库

## 放弃的方案与原因

- 阿里云 RDS：省运维，但内测阶段成本高；数据量上来后可以迁移
- GORM：隐式行为多，越权条件容易漏写；sqlc 让每条查询的归属条件都写在 SQL 里，审查时一眼可见

## 影响

- 备份、恢复演练由我们自己负责（T04 runbook）
- 改表必须写迁移文件，测试会对空库执行两次迁移以确认幂等
