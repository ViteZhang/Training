# 0009 功能开关支持「全部 / 指定用户」，关闭时接口返回 404

- 日期：2026-10-01
- 状态：已采纳

## 背景

首个版本一次开发全部页面，依赖外部条件的功能（在线支付、官方题库、口述背诵、语音作答、扫描版 PDF、邀请）
做好后先关闭，条件就绪再打开（PRD 3.4）。只有一套生产环境，上线前要在生产上对自己的账号打开自测。

## 决定

- feature_flags 表记全局开关（enabled_for_all），feature_flag_users 记只对哪些用户打开
- 服务端 internal/flags：全局开关缓存 30 秒，指定用户每次查；App 启动时随 /bootstrap 拉取，也可单独 GET /feature-flags
- 受开关控制的接口登记在 internal/http/flags.go 的 flagGuards（「方法 路由模板」→ 开关名），关闭时返回 404，与「不存在」不可区分
- App 只读服务端开关，关闭的功能不显示入口；离线时用上次缓存，从没拉到过一律视为关闭
- 后台 7.8 改开关后调用 Invalidate 立即生效（T29）

## 放弃的方案与原因

- 关闭时返回 403 或专门的错误码：旧版本 App 会把它当错误提示给用户；404 让入口不存在的语义一致
- 第三方开关服务：多一个外部依赖，内测规模用不上

## 影响

- 新增受控接口时，在 flagGuards 登记并补「关闭时 404」的测试
