# 0008 AI 能力层：按能力配置模型与提示词版本，JSON Schema 校验，灰度放量

- 日期：2026-10-02
- 状态：已采纳（主用模型待 Q02 / T31 定）

## 背景

首版有 18 项 AI 能力（PRD v3 12.1）。导入结构化、批改、作文批改决定产品能不能用，必须可评测、可回滚、能控成本；
模型会换（百炼上的通义千问、DeepSeek，另一家国内平台对照），提示词会反复迭代。

## 决定

- 业务代码只经 internal/ai 调用模型；internal/cloud/ai 只负责发请求（OpenAI 兼容接口，百炼与对照平台都用它）
- 每项能力是一个带类型的 `ai.Cap[In, Out]`：能力名、默认提示词版本、模型档位（strong / cheap）、温度、输出 JSON Schema、能力自己的校验、mock
- 提示词是 internal/ai/prompts/<能力>@<版本>.tmpl，系统提示与用户提示用 `---USER---` 分开；改提示词就加新版本文件，旧版本保留便于回滚与对比评测
- 灰度：ai_rollouts 每个能力一行，稳定版（模型 + 提示词版本）与候选版，候选版按用户比例放量；分桶 = sha256(能力:用户) % 100，同一用户稳定落在同一边；配置了不存在的提示词版本时回到代码默认版本，不让线上失败
- 每次调用：先按 Schema 校验，再跑能力校验（题干必须来自原文块、采分关键词必须在参考答案里、知识点原文必须在所在页逐字找到、采分点合计等于分值等）；不合格自动重试一次，再失败返回 AIFailed（「生成失败，未扣除次数」）；平台限流或网络错误不在这里重试，交给 Asynq 任务退避重试
- 每次调用写 ai_calls：能力、模型、版本、用户哈希（加盐）、token、费用、耗时、成败与错误类别；不存输入输出原文
- AI_PROVIDER=mock 时不发请求，能力的 Mock 按规则产出（开发、测试、CI 都不需要模型）
- 两档默认模型由 AI_MODEL_STRONG / AI_MODEL_CHEAP 配置（默认 qwen-max / qwen-plus），后台 7.8 可按能力在 ai_rollouts 覆盖
- 优先用高阶模型（2026-10-03 补充）：AI_PREFER_STRONG 默认开启，便宜档能力也用 STRONG；要省钱时关掉
- 中转为主、百炼备用（2026-10-03 补充）：AI_PROVIDER=relay 时主用 AI_RELAY_BASE_URL 的 OpenAI 兼容接口（默认 gpt-5.5）；同时配了百炼时，中转调用出错（网络、5xx、超时）当场改用百炼的高阶模型重发一次，两次都记 ai_calls。中转平台不是国内备案模型，只用于开发期试用与评测，不处理真实用户数据（见 open-questions）
- 评测：`make eval cap=import|kp|grading` 读 evals/private/*.jsonl，输出指标与是否达标；换模型或改提示词必须重跑

## 放弃的方案与原因

- 用模型平台的 function calling / 结构化输出保证格式：各平台支持程度不一，换平台要改代码；JSON 模式 + 服务端 Schema 校验在所有 OpenAI 兼容平台都能用
- 提示词放数据库：上线前要跑评测、走代码评审，放在仓库里版本清楚；数据库只放「用哪个版本」

## 影响

- 新增能力：写 Cap 定义、提示词文件、mock 与单元测试；批改（T18）、作文（T23）沿用
- 模型调用费用可按能力在 ai_calls 汇总（7.8）；价格表在 Engine 配置里，T31 定模型后补
