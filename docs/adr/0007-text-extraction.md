# 0007 文件取文本方案

- 日期：2026-10-01
- 状态：部分采纳（Word、Excel、粘贴已定；PDF、拍照、扫描件的服务待样本对比后定，见文末「待定」）

## 背景

导入流水线第 3 步要把资料取成带页码的文字（dev-spec 第六节「格式」表），后面切题、AI 结构化、出处页码、原文查看都依赖它。
格式：Word（.docx）、Excel（.xlsx）、粘贴文字、文字版 PDF、印刷体拍照、扫描版 PDF。旧版 .doc 与手写题目不支持。

## 决定

- **Word、Excel、粘贴文字在服务端用 Go 直接解析，不调用外部服务**（internal/extract）
  - .docx：解析 word/document.xml，保留段落、自动编号（按 numbering.xml 还原「一、」「1.」「(1)」等，切题靠它）、表格（第一行作表头，同时以「a | b」写进页面文字）；修订模式里删除的文字不要；每 1500 字一页并计 1 页，段落尽量不跨页
  - .xlsx：excelize 读表，每张可见工作表第一行非空行作表头，每行写成「表头：值」；每 50 行一页并计 1 页；提供导入模板（`api import-template`）
  - 旧版 .doc / .xls、加密文件（都是 OLE 复合文档）直接提示另存为新格式
- **PDF 与图片经 internal/cloud/ocr 的接口识别**：`Recognizer`（图片，返回文字与低置信度位置）、`PDFParser`（逐页返回文字、低置信度位置、是否扫描页）
  - 有文字层的页直接取文字，没有的逐页 OCR 并标为扫描页；PDF 按实际页数计费，图片每张 1 页
  - 含扫描页的 PDF 受功能开关 scanned_pdf 控制，关闭时整份标失败并提示改用拍照导入
- 文件本身的问题（格式不支持、损坏、照片没识别出文字、扫描版未开放）返回 UserError：资料标 failed、写明原因（1.6b 显示），任务不重试；网络与识别服务的错误由 Asynq 重试 3 次
- 本地与测试用 mock：图片字节当文字；PDF 按换页符分页，「[扫描]」开头的页当扫描页，【】内为低置信度

## 放弃的方案与原因

- 服务端用 Go 库解析 PDF 文字层（如 ledongthuc/pdf）：中文字体编码、分栏和表格还原效果不稳定，且扫描页终究要 OCR；统一交给识别服务，版面还原一致
- 服务端渲染 PDF 成图片再 OCR：需要 cgo（pdfium / mupdf），镜像变大，不如直接用支持 PDF 的服务

## 待定（需要样本与真实账号，T09 未完成部分）

候选（都在阿里云华北 2，与百炼同区域）：

| 候选 | 用于 | 要对比的 |
| --- | --- | --- |
| 文档智能 · 文档解析（大模型版） | 文字版 PDF、扫描版 PDF | 文字正确率、题号与表格还原、每页成本、100 页耗时 |
| 文字识别 OCR · 教育场景（试卷切题识别 / 题目识别） | 拍照、扫描页 | 文字正确率、题号切分、公式与下划线、每张成本、单张耗时 |
| 文字识别 OCR · 通用高精版 | 拍照、扫描页（对照） | 同上 |

对比方法：每种格式至少 2 个样本（真题汇编 PDF、讲义 PDF、手机拍的印刷体试卷、扫描版 PDF），放 evals/private/（不提交）；
逐字比对人工校对稿算字符正确率，题号、表格是否保留，记录每页成本与耗时；结论补到本文，并把选中的实现接到 OCR_PROVIDER。

## 影响

- 计费页数由取文本结果决定，导入流水线第 2 步的预占在 T10 按结果结算（失败页退回额度）
- material_pages 的 tables、low_confidence 为 JSON，可空列在 sqlc 里用 dbtypes.NullJSON
